# Secrets in a Spindle turn

**Status.** Draft. A reviewer wrote this note from the code at commit `f32f85a`, the settled readings in the milestone 1 plan, and the audit reports of milestone 1. The questions at the end are open. The project's lead has not answered them, and the answers will change this text.

**The rule.** Give a credential to the code that uses it. Keep it out of system messages. Preserve what the human and model said. Read the control fields of a tool result before masking it. At the last message write, replace known secret strings in text a tool or hook supplied, including keys and once-JSON-escaped text. At the terminal, mask the whole line, whoever wrote it. Preserve the few identifiers needed to join records.

### File and function key

Paths here are relative to `packages/runtime/src/`. A reference in a cell includes the functions in its key. “Log” includes the attempt records returned in memory as well as Effect warnings. There is no separate M1 database of provider diagnostics.

- H — `execution/trigger.ts`, `sendMessage`, `createThread` and `atRest`. The incoming turn uses writer `turn` before the loop starts. A store failure here is an Effect failure, outside the outcome.
- M — `execution/step.ts`, `responseMessage` and `runExecution`. Accepted response content, reasoning, reasoning details, arguments and tool-call extra content go to writer `turn`. Stored calls describe the model's call before schema coercion. “As written” describes redaction ownership. JSON parsing and serialization can change spelling or numeric precision, and storage normalizes ill-formed Unicode.
- W — `execution/tools.ts`, `storedResult`, `unstorableResult`, `resultOf`; `execution/messages.ts`, `createMessage`, `redactWrite`, `redactMetadata`. Result content, attachment names and descriptions, and error data are masked after the create hooks, even when a hook learned the string and left the field unchanged. For a turn, only fields whose final value differs from the original get this treatment. Branch selection uses the tool's initial status. The done hook receives the stored representation.
- B — `execution/tools.ts`, `redactAttachment`, spreads the reference and changes only name and description. Attachment path, ID, type and MIME type survive. Extra fields allowed through the structural check can survive storage too. `execution/assemble.ts`, `describeAttachment`, includes MIME type and path in request text. An injection's string value under error_code still gets masked.

## Threat model

The protected material is a resolved credential or other classified string. The tool or hook that requested it and the provider it authenticates to may need the original bytes. A model, ordinary database record, terminal, log and client should never receive those bytes by accident. An authorized transport receiving a bearer header is different from the model receiving the bearer token in a message.

M1 protects selected runtime-managed routes against ordinary mistakes such as returning a whole error object or injecting a message containing an env value. It does not isolate packaged JavaScript. A developer with access to a credential can encode it, write files, print it or send it elsewhere. A tool can also call another tool and receive its raw result in process. Install only code trusted with the credentials it can resolve.

## Where a protected string comes from

Spec citations below are relative to `content/0.2.0/` at `f462a673297faed1f849ef1741ddda1e06b6c817`. The MIT package supplies the signatures. The text supplies the behavior.

- **Instance env.** The M1 lookup walks agent env, prompt tool-entry env where applicable, prompt env and finally instance config. A direct instanceEnv read skips definitions. A resolved instance value enters both the replacement set and the system-prompt barred set, including when a prompt declares its name as text. Spindle looks up named variables, without enumerating the environment. The spec's full order also includes thread first and user before instance. An absent instance key resolves to `undefined` through `instanceEnv`. If the configuration source fails, both `instanceEnv` and an `env` lookup that reaches the instance reject with a read error. Learning secrets before a run reads every declared name, and there a value that cannot be read is treated as absent, so that a variable nobody reads cannot fail a run or the creation of a thread. Such a value is then not redacted if a later read of it succeeds. See `execution/env.ts`, `lookupEnv` and `instanceEnv`, and `specification/threads.md:220–240`.
- **Declared variables and definition defaults.** `execution/step.ts:198–215`, `learnSecrets`, collects secret names across the active prompt and its exposed tools, including names learned from provider resolution. It resolves declared scopes and secret names at prompt scope before dispatch. A definition-supplied value of a secret name enters both sets. Ordinary definition defaults are eligible for declared text interpolation. A call to state.env nevertheless adds even a text default to the replacement set, without barring it from system text. The public envType always answers secret in M1. These are three different answers to “is this secret?” The discovery scan covers exposed tools, not every transitive uses target. A nested-only declaration is not itself registered by executeTool. See `execution/thread-state.ts`, `makeThreadState`, `execution/tools.ts`, `scopeFor` and `invokeTool`; `specification/tools.md:48–64`, `specification/prompts.md:103–125`, `specification/threads.md:236`.
- **Provider config.** A configured extension source wins over a base slot. An env source tries instance then its own default. An unoverridden slot tries defaultEnv then its slot default. A secret slot can learn a string constant or literal fallback without an env read. Nested maps resolve leaf by leaf. Secret env leaves register their names too. Only string values enter the sets. An explicit source valueType takes precedence over the slot type for an env source. Unlike state.env, a non-secret-typed provider slot or leaf does not register its instance value solely because of its source. The OpenAI-compatible base declares OPENAI_API_KEY secret and OPENAI_BASE_URL URL. See `providers/config.ts`, `fromSource`, `fromSlot`, `learn`; `specification/providers.md:110–170`, `infrastructure/providers.md:112–129,205–212`.
- **Caller and scope.** ExecutionOptions.secrets may seed replacement values. newSecrets starts fresh name and barred sets even when it shares the values set. createThread's at-rest hooks get a separate collection. sendMessage can share its replacement set with the run when the caller provides one. Independent stateAtRest handles also have their own collection. Knowledge acquired by one writer is not automatically available to another.
- **Future sources.** The package declarations in `packages/runtime/node_modules/@standardagents/spec/dist/index.d.ts:2645–2652,2960–2972` give envType a promise of EnvValueType and setEnv a string name, string value, optional SetEnvOptions with optional type, and a promise of void. M1 stubs setEnv. The spec preserves the existing type when omitted and defaults a new key to secret. Durable scoped propagation and encryption are addressed in `specification/threads.md:236–242`. Draft user grants have a stronger contract: only existence and metadata are readable, and the runtime injects the credential on an authorized request. Even packaged code must never read grant material. See `specification/users.md:184–205`.

## Limits and gaps

Use distinct high-entropy strings. Every nonempty length counts, including one character. A common word can spoil ordinary prose, block a system prompt, or make a serialized CLI dump invalid JSON. The replacement algorithm in `execution/redact.ts` sorts longer secrets first and tries their literal and once-JSON-escaped spellings. Two keys can collapse to the same key, with the later value winning. Do not rely on value matching for numbers, booleans, substrings revealed in pieces, repeated escaping, URL encoding or base64. Never place a credential in an identifier. A store read returns the durable row, without a new screen using today's secrets.

The table has **16 marked cells**. They are direct discrepancies with the stated rules. The **17 gap families** below also include routes the rules leave undecided. Counts group repeated uses of the same failing boundary, rather than counting downstream copies as new root causes.

1. Human and model history can carry credentials back to the model. Canonical storage is explicitly accepted. Replay is a separate disclosure, including reasoning, call arguments and extra content.
2. Attachment MIME text and extra JSON properties pass through result and create-hook storage. MIME text is rendered into model input. Attachment ID and path have identity uses. Arbitrary extra text does not.
3. A create hook's proposed ID is checked with the secrets known at that hook's return. A later hook can learn the value and leave the ID unchanged. Final field redaction excludes the ID. A collision warning may include it.
4. A thread-created hook can learn an undeclared value in its private collection while another at-rest hook selects an ID before that discovery. A later run trace or CLI logger outside that collection can print the value. At-rest hooks also have access to a different secret set from the run's logger during creation.
5. A request-history hook can learn a new barred literal after the leading system string passed its check. Only history is rechecked. Caller-seeded replacement values alone also do not bar a system string. Escaped-only spelling is outside the literal system scan. The spec prohibits secrets in system prompts and requires sanitization of untrusted input. Literal matching alone does not sanitize arbitrary instructions. See `specification/prompts.md:42–50,84–91`.
6. Either request filter can introduce raw user, assistant or tool content, multipart content, arguments or reasoning. Validation checks shape. The project documents this behavior in `packages/conformance/DIVERGENCES.md:135`; the lead's accepted exceptions only cover storage and identifying fields.
7. setValue can persist raw strings in keys or values outside message hooks. Keep credentials out of general thread state.
8. Library warning sinks receive hook IDs, positions and runtime prose without the CLI mask. Hook exceptions are deliberately omitted. Supply a redacting logger when embedding Spindle.
9. A provider controls origin text, which survives structured error handling. A diagnostic identifier can contain arbitrary provider-supplied text.
10. The metadata walker returns non-plain objects and cyclic back-edges unchanged. A provider metadata object that a caller later formats or serializes can expose raw text. Message-storage JSON validation does not protect the in-memory call log.
11. Pre-loop store failures from sendMessage or createThread bypass settle. CLI handling masks its diagnostic, but a library caller gets the failure channel.
12. Definition descriptions, parameter schemas and provider options reach the provider unscanned. Definition identifiers can also reach storage, call logs and outcomes. Keep configuration credentials in transport slots.
13. URL, text or untyped provider env config can contain an instance credential unknown to the CLI or prompt guard. A failed prepareTurn can also leave preflight learning incomplete before validation or setup diagnostics print. The command masks what it knows.
14. An early trace detail can contain a then-unknown value. Later discovery does not rescan the trace array at settlement.
15. A library observer receives the original request or stored message object. The CLI applies its mask in its own observer. Never forward the library event stream verbatim to a client.
16. Native console output from trusted code and application-managed logging have no runtime mask. Even an accidental console.log inside a tool reaches the terminal.

17. A secret declaration on a tool reachable only through invokeTool is outside the initial declaration scan. A definition default copied into a result or request before any tracked read can pass. Reading it with state.env registers the value for replacement, but only source or an already known secret name bars it from system text.

### Questions for the lead

1. Should a definition default inherit the spec's non-thread default of secret, or should its declaration classify it as M1 does? For typed thread values, settle whether envType, output masking and the system-prompt guard must agree. Decide whether instance-derived provider URL and text slots share that classification.
2. Should every model-bound request get one final check after all hooks, including nested prompts, tool schemas, options and replayed history? Today the leading prompt and history have separate checks, and non-system hook output and definition schemas pass. One alternative preserves canonical storage while refusing unsafe dispatches.
3. Where does trusted in-process access end? Today a handler-like tool can persist arbitrary KV data, an observer gets raw events, and each execution owns its knowledge. An alternative gives private typed storage a separate contract and makes outcomes, endpoints and client streams share a public projection with explicit fields and redaction at delivery.
