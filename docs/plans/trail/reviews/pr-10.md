# Code quality review: PR 10 (`m1/7-chat`, `spindle chat`)

Reviewed at `origin/m1/7-chat` (`43a4d5b`) against base `origin/m1/6-queue` (`6d5a778`), checked against `docs/plans/briefs/m1-7.md`, `docs/design/thread-ownership.md`, the 44 child-process tests in `packages/runtime/test/cli/chat*.test.ts`, the PR 8 tests in `packages/runtime/test/cli/queue.test.ts`, and `effect@4.1.5` declarations in `node_modules/effect/dist/`.

## 1. Verdict

PR 10 does not meet the approval bar. Every behavior in the 44 tests works, but the command's core function, `converse` in `packages/runtime/src/cli/chat.ts:151-309`, packs six distinct jobs into one 159-line generator that coordinates seven mutable variables across three to four fibers (`own`, `cursor`, `previous`, `waiting`, `atPrompt`, `admitted`, `stopping`, plus `lastAdmission` mutated out into `chatCommand`), patched in place with a `Semaphore`, `Effect.orDie`, and a sequence of ordering fixes that still leave subtle races. Alongside `converse`, `chat.ts` duplicates four full startup/plumbing blocks from `cli/run.ts` (plus partial output formatters) and adds a third reporting channel in `ThreadSupervisor.send` for a waiting line instead of unifying the two that PR 8 already had.

## 2. Structural findings

### S1. `converse` shares seven mutable variables across three to four fibers instead of running one event-consuming state machine

- **Location:** `packages/runtime/src/cli/chat.ts:151-309`, `packages/runtime/src/cli/chat.ts:363-399`
- **Cost to maintainers:** Six responsibilities (terminal/SIGINT wiring, store cursor flushing, aborted-run carry-over, live/remote observation, Ctrl-C/closed-output turn waiting, and the prompt loop) read and write seven mutable variables (`own`, `cursor`, `previous`, `waiting`, `atPrompt`, `admitted`, `stopping`, plus `ending` and `chatCommand`'s `lastAdmission`) from up to four fibers (main loop, forked `send`, execution fiber calling `observe`, and `onWaiting`'s 50ms `forkChild` poll). Four of the post-build commits (`0779a70`, `b45315a`, `ba5b182`, `bd7b89f`) were ordering bugs among those variables, and three latent faults remain: `observe` calls `Effect.orDie` (`chat.ts:199`) so a `SqlError` during `flush` kills the execution fiber with a defect; `onWaiting` forks its 50ms poll loop even when waiting behind a local aborted run and leaves it spinning until the turn ends even after `waiting` turns `false` (`chat.ts:222-229`); and `waiting` is `false` until `onWaiting` runs, so a Ctrl-C arriving between `send` and `onWaiting` while an aborted local tool still holds the thread can misclassify the wait as a stoppable run (`chat.ts:262`).
- **Proposed restructuring:** Replace `converse`'s cross-fiber mutable state and `Semaphore` with one fiber owning all conversation state (`phase`, `aborted`, `cursor`, `own`), consuming a single FIFO `Queue<ChatEvent>`, with `Scope` owning prompt/turn/poll lifetimes and an explicit uninterruptible `finishChat` phase after `converse`'s scope closes.

  **Sketch of the types and ownership:**

  ```ts
  type WaitingHolder =
    | { readonly kind: "remote"; readonly pid: number }
    | { readonly kind: "local"; readonly pid: number; readonly abortedOperation?: string }

  interface ActiveTurn {
    readonly id: number
    readonly scope: Scope.Closeable
    readonly admitted: boolean
  }

  type Phase =
    | { readonly _tag: "Prompting"; readonly promptScope: Scope.Closeable }
    | { readonly _tag: "Running"; readonly turn: ActiveTurn }
    | { readonly _tag: "Waiting"; readonly turn: ActiveTurn; readonly pollScope: Scope.Closeable }
    | { readonly _tag: "Stopping"; readonly turn: ActiveTurn }
    | { readonly _tag: "ClosingOutput"; readonly turn: ActiveTurn }

  type AbortedRun =
    | { readonly _tag: "None" }
    | { readonly _tag: "Draining"; readonly settled: Effect.Effect<RunOutcome, unknown> }
    | { readonly _tag: "Settled"; readonly outcome: RunOutcome }

  type ChatEvent =
    | { readonly _tag: "Input"; readonly line: string | null }
    | { readonly _tag: "Interrupt" }
    | { readonly _tag: "OutputClosed" }
    | { readonly _tag: "AbortedSettled"; readonly settled: Effect.Effect<RunOutcome, unknown>; readonly exit: Exit.Exit<RunOutcome, unknown> }
    | { readonly _tag: "Admitted"; readonly turnId: number; readonly seq: number }
    | { readonly _tag: "Waiting"; readonly turnId: number; readonly holder: WaitingHolder }
    | { readonly _tag: "Observe"; readonly turnId: number; readonly event: ExecutionEvent; readonly ack: Deferred.Deferred<void> }
    | { readonly _tag: "Poll"; readonly turnId: number }
    | { readonly _tag: "TurnDone"; readonly turnId: number; readonly exit: Exit.Exit<Delivery, unknown> }
  ```

  **What each function owns:**
  - `openConversation(chat)`: scoped resource (`Effect.scoped` boundary). Acquires `openChatTerminal`, `onInterrupt` (offering `{ _tag: "Interrupt" }` via `Queue.offerUnsafe`), `events = Queue.unbounded<ChatEvent>()`, `loopEnded = Deferred.make<void>()`, and a scoped watcher fiber on `terminal.outputClosed` that offers `{ _tag: "OutputClosed" }`. Registers a finalizer that completes `loopEnded` and shuts down `events` so no producer can hang.
  - `flush()` & `finishAborted()`: private to the single consumer fiber. Because no other fiber ever touches `cursor`, `own`, `aborted`, or `terminal.write`, the `Semaphore` (`chat.ts:166`) disappears completely.
  - `enterPrompt()`: forks a child `promptScope` and starts ONE single-shot fiber `terminal.readLine -> Queue.offer(events, { _tag: "Input", line })` inside `promptScope`. Closing `promptScope` on `Interrupt`, `OutputClosed`, or `Input` guarantees chat reads only at the prompt and drops no piped lines.
  - `startTurn(line)`: creates a fresh `turnId`, forks a `turnScope`, and forks `supervisor.send(...)` in `turnScope`. Its callbacks only emit events (no shared state mutation except recording `lastAdmission` synchronously in a `Ref` passed in from `chatCommand` — see check below):
    - `onAdmitted(seq)`: writes `lastAdmission` synchronously (for SIGTERM-vs-admit races) AND offers `{ _tag: "Admitted", turnId, seq }`.
    - `onWaiting(holder)`: offers `{ _tag: "Waiting", turnId, holder }`.
    - `observe(event)`: creates `ack = Deferred.make<void>()`, offers `{ _tag: "Observe", turnId, event, ack }`, and awaits `Effect.raceFirst(Deferred.await(ack), Deferred.await(loopEnded))`. No `Effect.orDie`; DB errors stay typed inside the consumer fiber!
    - On exit of `send`: offers `{ _tag: "TurnDone", turnId, exit }`.
  - `step(state, event)` (via `Match.tagsExhaustive` on `event._tag` and `state.phase._tag`):
    - Any turn-scoped event whose `turnId` does not match the active turn is ignored immediately (resolving `ack` if `Observe`), making stale events from an aborted turn impossible to confuse with the active turn.
    - `AbortedSettled`: if `Prompting`, stores `{ _tag: "Settled", outcome }` and **prints nothing**; if active (`Running`/`Waiting`/`Stopping`), flushes and reports immediately and resets to `None`.
    - `Input(line)` in `Prompting`: closes `promptScope`; if `line === null`, exits with `"input"`; echoes `line` when `!terminal.isTerminal`; if blank, checks `requireOpen` and re-enters `Prompting`; otherwise flushes any `AbortedRun.Settled` (`flush` + `report`) and any missed records (F23), then enters `Running` via `startTurn(line)`.
    - `Observe`: if `aborted._tag === "Draining"` (necessary because `ThreadSupervisor.ts:184-187` starts the successor execution before completing `entry.done`), awaits `aborted.settled`, flushes, reports, sets `aborted = None`; if phase was `Waiting`, closes `pollScope` and transitions to `Running`; handles `message` (`flush`), `trace`, `request`; checks `terminal.isOutputClosed` *before* succeeding `ack` — if closed, immediately calls `supervisor.stop` and transitions to `ClosingOutput` before unblocking `step.ts`; finally succeeds `ack`.
    - `Waiting`: prints O11; forks the 50ms `Poll` fiber in `pollScope` **only** when `holder.kind === "remote"`; transitions to `Waiting`.
    - `Poll`: only handled in `Waiting` -> `flush`.
    - `Interrupt`: in `Prompting` or `Waiting`, closes phase scope and exits with `"input"`; in `Running`, calls `supervisor.stop(chat.id)` (if `false`, exits `"input"`, else prints O8 and enters `Stopping`); in `Stopping`, prints O9, calls `supervisor.abort(chat.id)` (see S4), closes `turn.scope`, forks a scoped waiter `settled -> AbortedSettled`, sets `aborted = Draining(settled)`, and enters `Prompting`; in `ClosingOutput`, ignored.
    - `OutputClosed`: in `Prompting` or `Waiting`, closes phase scope and exits with `"closed"`; in `Running` or `Stopping`, calls `supervisor.stop(chat.id)` — if `true`, enters `ClosingOutput` and waits for `TurnDone`, else exits `"closed"`.
    - `TurnDone`: closes `turn.scope` (and `pollScope` if `Waiting`); if in `ClosingOutput`, exits with `"closed"`; if `Exit.isSuccess`, drains `aborted` if `Draining`/`Settled`, flushes, checks `requireOpen`, calls `report`, enters `Prompting`; if `Exit.isFailure`, re-fails on `ThreadTerminated`, else prints O12 using `turn.admitted` (guaranteed ordered after `Admitted` by queue FIFO) and enters `Prompting`.
  - Exit path (`chatCommand`): runs `openThread` *outside* `Effect.uninterruptibleMask`, then wraps only `restore(converse(...).pipe(Effect.scoped))` and `finishChat` in `uninterruptibleMask` (because `Scope` finalizers in Effect have error channel `never` and cannot produce exit-code-1 failures like missing DB or `ThreadTerminated`, while `Effect.scoped` guarantees every turn/poll/terminal fiber is torn down before `finishChat` runs `fs.exists`, `requireOpen`, `store.isQueued`, and O14).

  **Checked against all 44 tests:**
  - `chat.test.ts` (22 tests): initial `flush` before first `enterPrompt` prints `after_thread_created` `[elsewhere]` notes (`chat.test.ts:541-557`); single-shot `readLine` in `Prompting` preserves piped multi-line ordering and backpressure for 200k-char lines (F07, F08); `fs.exists` first in `finishChat` preserves deleted-DB reporting (F26).
  - `chat-interrupt.test.ts` (13 tests): `AbortedSettled` stays silent during `Prompting`, printing closing records and O10 only on the next line (F16) and never on 3rd Ctrl-C exit (F18); awaiting `aborted.settled` on the successor's first `Observe` handles `ThreadSupervisor.ts:184-187` starting the successor before resolving `done`, including two consecutive aborted tools (`chat-interrupt.test.ts:56-93`, F17); synchronous `lastAdmission` write in `onAdmitted` preserves the `SIGTERM`-vs-admit race check (`chat-interrupt.test.ts:122-151`); EOF during a run prints the final `> ` before exiting because `TurnDone` transitions to `Prompting` and reads `null` (F14, `chat-interrupt.test.ts:211`).
  - `chat-shared.test.ts` (9 tests): remote `pollScope` flushes remote holder records live (F03); `Observe` checking `isOutputClosed` before completing `ack` guarantees `supervisor.stop` runs before `step.ts` starts the next model call on EPIPE (F25, `chat-shared.test.ts:297-325`); FIFO `Admitted` before `TurnDone` distinguishes pre- vs post-admission DB lock failures (`chat-shared.test.ts:83-105, 259-294`); `requireOpen` on blank line, `TurnDone`, and `finishChat` covers all external termination paths (`chat-shared.test.ts:38-80`).
- **Line estimate:** Replaces 159 lines of `converse` with ~175 lines of typed state/transitions (net ~+15 lines in `converse` itself, but deletes `Semaphore`, all 7 cross-fiber mutable variables, and all ad-hoc guards, and combines with S3 to bring `chat.ts` down from 415 lines to ~290 lines).
- **Risk & tests:** Medium behavioral surface because exact stdout/stderr ordering is asserted line-for-line; guarded by all 44 tests in `packages/runtime/test/cli/chat.test.ts`, `chat-interrupt.test.ts`, and `chat-shared.test.ts` (no test edits needed).
- **PR & ripple:** PR 10 (`m1/7-chat`); zero upward ripple (top of stack).
- **Effect APIs verified:** `Queue.unbounded`, `Queue.offer`, `Queue.offerUnsafe`, `Queue.take`, `Queue.shutdown` (`node_modules/effect/dist/Queue.d.ts`); `Scope.fork`, `Scope.close` (`Scope.d.ts:496, 580`); `Effect.forkIn`, `Effect.scoped`, `Effect.uninterruptibleMask`, `Effect.raceFirst` (`Effect.d.ts:13059, 15051, 17777`); `Deferred.make`, `Deferred.await`, `Deferred.succeed` (`Deferred.d.ts:152-153, 1405`); `Ref.make`, `Ref.get`, `Ref.set` (`Ref.d.ts:154-217`); `Match.tagsExhaustive` (`Match.d.ts:1132`).

### S2. Three channels report a waiting line (and three report a still-queued line)

- **Location:** `packages/runtime/src/execution/ThreadSupervisor.ts:20-33, 346-378`, `packages/runtime/src/execution/step.ts:68-69`, `packages/runtime/src/cli/run.ts:68-72, 213`, `packages/runtime/src/cli/chat.ts:190, 218-235, 389`
- **Cost to maintainers:** The audit's claim is **confirmed**. Right inside `ThreadSupervisor.send`, waiting behind a holder is reported through three separate channels at once:
  1. `options.onWaiting(holder)` (`ThreadSupervisor.ts:32, 349, 359`) — added by PR 10 for `chat.ts`, firing for both local aborted holders and remote holders.
  2. `options.observe({ type: "queued", threadId, pid })` (`step.ts:68`, `ThreadSupervisor.ts:360-361`) — added by PR 8 for `run.ts`/`send.ts`, firing on the very next line after `onWaiting` for remote holders only, and explicitly discarded by `chat.ts:190` (`if (atPrompt || event.type === "queued") return`).
  3. `Delivery.elsewhere` (`ThreadSupervisor.ts:25, 358, 377`) — recorded on the return value and read by **zero** callers anywhere in the repository.

  A matching three-way split exists for "interrupted while still queued": `observe({ type: "interrupted_while_queued" })` (`step.ts:69`, `ThreadSupervisor.ts:368`, used only by `run.ts:68`), `Delivery.stillQueued` (`ThreadSupervisor.ts:21, 377`, used only by `run.ts:213`), and `onAdmitted` + `store.isQueued` (`chat.ts:389`). Neither `"queued"` nor `"interrupted_while_queued"` is an execution event — `step.ts` never emits either of them.
- **Proposed restructuring:**
  1. Delete dead `Delivery.elsewhere` (`ThreadSupervisor.ts:25, 338, 358, 377`).
  2. Remove `"queued"` and `"interrupted_while_queued"` from `ExecutionEvent` in `step.ts:68-69` so `ExecutionEvent` holds only events `step.ts` actually emits (`trace`, `message`, `request`).
  3. Standardize `SendOptions` in `ThreadSupervisor.ts` on one `onWaiting(holder: WaitingHolder)` callback (discriminating `{ kind: "local"; pid: number; abortedOperation?: string } | { kind: "remote"; pid: number }`) plus `onAdmitted(seq: number)` and optional `onInterruptedWhileQueued?: () => Effect.Effect<void>` (or let `run.ts` use `onAdmitted` + `Effect.onInterrupt` just like `chat.ts` does!). Both `run.ts`/`send.ts` and `chat.ts` wire `onWaiting`; `chat.ts` drops `event.type === "queued"` and starts remote polling only when `holder.kind === "remote"`.
- **Line estimate:** Removes ~25 lines across `ThreadSupervisor.ts`, `step.ts`, `run.ts`, and `chat.ts`, and eliminates two dead/redundant protocol shapes.
- **Risk & tests:** Low; `queue.test.ts` (PR 8) and `chat-shared.test.ts` / `chat-interrupt.test.ts` (PR 10) assert exact stderr lines for both `send` and `chat`. No conformance scenario reads `Delivery.elsewhere` (verified by repo-wide grep).
- **PR & ripple:** PR 8 (`m1/6-queue`) should delete `Delivery.elsewhere` and move `"queued"` / `"interrupted_while_queued"` off `ExecutionEvent` onto `SendOptions`; PR 10 extends `WaitingHolder` with `abortedOperation`. Ripples PR 8 -> PR 10.
- **Effect APIs verified:** `Effect.Effect`, `Effect.onInterrupt` (`Effect.d.ts:14918`).

### S4. `ThreadSupervisor.abortExecution` duplicates `abort`, leaks an internal mutable `Deferred`, and `stop` returns `true` for already-aborted runs

- **Location:** `packages/runtime/src/execution/ThreadSupervisor.ts:54-58, 313-322, 388-397`; `packages/runtime/src/cli/chat.ts:266, 289`
- **Cost to maintainers:**
  1. `ThreadSupervisor` now has two abort methods that execute the exact same body: `abort` (`396-397`) is literally `Effect.map(abortExecution(threadId, exiting), (settlement) => settlement !== undefined)`.
  2. `abortExecution` returns the supervisor's internal mutable `local.done` (`Deferred.Deferred<RunOutcome, unknown>`). Any caller can complete or fail that `Deferred` and corrupt supervisor settlement, and it pushed `chat.ts:289` into calling `Deferred.isDoneUnsafe`.
  3. `stop(threadId)` (`388-394`) checks only `local === undefined || local.run.ended`, ignoring `local.run.abort.signal.aborted`. While an aborted tool is still running (`ended === false`), `stop()` returns `true`, which makes `chat.ts:262` mistake an already-aborted run for a cooperatively stoppable run if Ctrl-C lands before `onWaiting` runs.
- **Proposed restructuring:**
  1. Remove `abortExecution` and have `abort(threadId, exiting?)` return `Effect.Effect<Option.Option<Effect.Effect<RunOutcome, ...>>>` — a read-only awaitable effect (`Deferred.await(local.done)`) wrapped in `Option.some`, or `Option.none()` if no live run exists. Update its three existing callers: `run.ts:263` (`Option.isSome`), `test/spindle-driver.ts:169` (`Option.isSome`), and `chat.ts:266` (passes the awaitable directly to its scoped waiter). `test/execution/hooks.test.ts:76` ignores the return value and needs no change.
  2. Guard `stop`: `if (local === undefined || local.run.ended || local.run.abort.signal.aborted) return false`.
- **Line estimate:** Removes ~10 lines in `ThreadSupervisor.ts` and deletes raw `Deferred` imports/calls in `chat.ts`.
- **Risk & tests:** Low; verified all callers of `.abort(` and `.abortExecution(` across the entire repo (only 4 call sites total). Guarded by `chat-interrupt.test.ts`, `queue.test.ts`, `ownership.test.ts`, and `hooks.test.ts`.
- **PR & ripple:** Carry the `stop` guard and unified `abort` return type in PR 8 (`m1/6-queue`), rippling cleanly into PR 10 (`chat.ts`) with no separate `abortExecution` method ever added.
- **Effect APIs verified:** `Option.Option`, `Option.some`, `Option.none`, `Option.isSome`; `Deferred.await` (`Deferred.d.ts:153, 190`).

### E1. `unknown` in `ThreadSupervisor` error channels forces `Cause.squash` and `instanceof` checks throughout `chat.ts` and `run.ts` (`anyUnknownInErrorContext`)

- **Location:** `packages/runtime/src/execution/ThreadSupervisor.ts:38, 51, 58, 60-61, 268`; `packages/runtime/src/cli/chat.ts:137, 177, 184, 192, 211, 246, 252-253, 289, 294, 298, 369, 397, 404-409`
